# Нейросетевая система выявления аномального стиля поведения клиентов в целях финансового мониторинга

## Описание проекта

Данный проект представляет собой программную реализацию практической части выпускной квалификационной работы на тему:  
**«Нейросетевая система выявления аномального стиля поведения клиентов в целях финансового мониторинга»**.

Разработанный прототип предназначен для автоматизированной обработки транзакционных данных клиентов, расчета показателя аномальности, определения уровня риска и визуального представления результатов анализа. Система позволяет загружать данные в формате CSV, передавать их на серверную обработку, получать итоговую оценку риска и отображать результаты в виде таблиц, графиков и аналитических блоков.

Программное решение включает пользовательский интерфейс, серверную часть и нейросетевое ядро, выполняющее оценку отклонений в поведении клиентов по совокупности признаков.

## Цель практической реализации

Целью разработки является создание программного прототипа системы, позволяющей выявлять аномальные операции клиентов на основе транзакционных признаков и представлять результаты анализа в удобной для пользователя форме.

## Основные возможности системы

В рамках проекта реализованы следующие функции:

- загрузка транзакционных данных из CSV-файла;
- авторизация пользователя перед доступом к аналитической панели;
- отображение реестра операций;
- автоматический расчет итогового балла аномальности;
- определение уровня риска по каждой операции;
- визуализация распределения рисков;
- выделение наиболее рискованных клиентов;
- пояснение факторов, повлиявших на итоговую оценку риска;
- формирование рекомендованного действия по выбранной операции;
- проверка работы серверной части через endpoint `/health`;
- обмен данными между frontend- и backend-компонентами.

## Описание основных частей проекта

### `backend/`

Серверная часть приложения.  
В файле `main.py` реализованы API, обработка входных транзакций, нейросетевое ядро и расчет итоговой оценки риска.  
Файл `requirements.txt` содержит зависимости Python, необходимые для запуска backend-части.

### `src/components/`

Каталог с компонентами пользовательского интерфейса.  
В нем размещены отдельные блоки аналитической панели: загрузка данных, графики, таблица операций, пояснение риска, итоговая сводка и блок наиболее рискованных клиентов.

Компонент `AuthScreen.jsx` отвечает за экран авторизации пользователя, проверку доступности backend-сервера и передачу токена доступа в основное приложение.

### `src/utils/`

Каталог со вспомогательными функциями и данными.  
Здесь находятся функции обработки CSV, преобразования результатов анализа, пояснения риска и демонстрационные наборы данных.

### `src/App.jsx`

Главный компонент frontend-части.  
Он хранит состояние приложения, отправляет данные на backend, получает результаты анализа и собирает интерфейс из отдельных компонентов.

### `src/App.css`

Основной файл стилей приложения.  
Используется для оформления аналитической панели, карточек, таблиц, графиков и кнопок.

### `src/main.jsx`

Точка входа React-приложения.

## Формат входных данных

Для анализа используется CSV-файл со следующей структурой:

```csv
client_id,timestamp,amount,frequency,channel,category
C001,2026-04-01 09:15,12000,3,online,transfer
C002,2026-04-01 10:20,95000,12,online,cashout
C003,2026-04-01 11:00,2400,2,mobile,payment
```

### Описание полей

| Поле        | Описание                  |
| ----------- | ------------------------- |
| `client_id` | Идентификатор клиента     |
| `timestamp` | Дата и время операции     |
| `amount`    | Сумма операции            |
| `frequency` | Частота операций клиента  |
| `channel`   | Канал проведения операции |
| `category`  | Категория операции        |

## Инструкция по запуску проекта

Открыть в редакторе кода пустую папку, в которую будет загружен проект, и выполнить команду клонирования репозитория из GitHub:

```bash
git clone https://github.com/nagovskiy/anomaly-monitoring-panel.git .
```

Для корректной работы необходимо запустить две части проекта: frontend и backend.

## 1. Запуск backend-части

Установить Python.

Перейти в папку серверной части:

```bash
cd backend
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Запустить сервер:

```bash
python -m uvicorn main:app --reload --port 8000
```

После успешного запуска в терминале должна появиться строка:

```text
Uvicorn running on http://127.0.0.1:8000
```

Проверить работоспособность backend можно по адресу:

```text
http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```json
{ "status": "ok" }
```

## 2. Запуск frontend-части

Открыть второй терминал.

Установить Node.js.

Перейти в корневую папку проекта, куда был склонирован репозиторий.

Установить зависимости frontend-части:

```bash
npm install
```

Запустить frontend:

```bash
npm run dev
```

После запуска приложение будет доступно по адресу:

```text
http://localhost:5173/
```

При открытии интерфейса сначала отображается экран авторизации.

Демонстрационные учетные данные:

```text
Логин: analyst
Пароль: analyst123
```

После успешного входа пользователь получает доступ к аналитической панели.

## Порядок использования приложения

1. Запустить backend-сервер на порту `8000`.
2. Запустить frontend-приложение через команду `npm run dev`.
3. Открыть веб-интерфейс в браузере по адресу `http://localhost:5173/`.
4. Выполнить вход в систему с демонстрационными учетными данными:
   - логин: `analyst`;
   - пароль: `analyst123`.
5. Использовать демонстрационные данные или загрузить собственный CSV-файл.
6. После загрузки данных система автоматически выполнит анализ.
7. В интерфейсе будут отображены:
   - сводные показатели;
   - графики распределения риска;
   - реестр операций;
   - уровень риска по каждой записи;
   - пояснение причин риска;
   - топ-3 наиболее рискованных клиентов.

## API backend-части

### Проверка состояния сервера

```http
GET /health
```

Пример ответа:

```json
{
  "status": "ok"
}
```

### Авторизация пользователя

```http
POST /login
```

Пример входных данных:

```json
{
  "login": "analyst",
  "password": "analyst123"
}
```

Пример ответа:

```json
{
  "access_token": "token",
  "token_type": "bearer",
  "user": "analyst"
}
```

### Анализ транзакций

```http
POST /analyze
```

Для выполнения анализа необходимо передать токен авторизации в заголовке:

```http
Authorization: Bearer <access_token>
```

Пример входных данных:

```json
{
  "transactions": [
    {
      "client_id": "C001",
      "timestamp": "2026-04-01 09:15",
      "amount": 12000,
      "frequency": 3,
      "channel": "online",
      "category": "transfer"
    }
  ]
}
```

Пример ответа:

```json
{
  "summary": {
    "total": 1,
    "low": 0,
    "medium": 1,
    "high": 0,
    "average_score": 54.2
  },
  "results": [
    {
      "client_id": "C001",
      "timestamp": "2026-04-01 09:15",
      "amount": 12000,
      "frequency": 3,
      "channel": "online",
      "category": "transfer",
      "reconstruction_error": 0.034512,
      "anomaly_score": 54.2,
      "risk_level": "Средний",
      "flag": "Нужно наблюдение"
    }
  ],
  "user": "analyst"
}
```

## Практическая значимость

Разработанный прототип демонстрирует возможность применения нейросетевого подхода для автоматизированной оценки транзакционной активности клиентов. Система позволяет не только рассчитать уровень риска, но и представить результат в наглядной форме, что повышает удобство анализа и может быть использовано при дальнейшем развитии систем финансового мониторинга.

## Особенности реализации

В проекте предусмотрены демонстрационные сценарии нормального и аномального поведения. Это позволяет проверить работу модели без обязательной загрузки внешнего файла. Также реализован блок пояснения риска, который показывает факторы, повлиявшие на итоговую оценку операции.
